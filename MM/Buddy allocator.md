Buddy allocator — это алгоритм управления памятью, который выделяет и освобождает память блоками, размер которых равен степени двойки. Его часто используют в операционных системах, например в ядре Linux, потому что он быстро находит свободные блоки и быстро объединяет их обратно после освобождения.

## 1. Главная идея Buddy allocator

Допустим, у нас есть большой непрерывный участок памяти:

```text
1024 КБ
```

Buddy allocator делит память не на произвольные куски, а на блоки размеров:

```text
1024 КБ
512 КБ
256 КБ
128 КБ
64 КБ
32 КБ
16 КБ
...
```

То есть каждый блок можно разделить пополам на два одинаковых блока. Эти два блока называются **buddy**, то есть «напарники» или «близнецы».

Например:

```text
1024 КБ
├── 512 КБ
│   ├── 256 КБ
│   └── 256 КБ
└── 512 КБ
    ├── 256 КБ
    └── 256 КБ
```

Каждая пара блоков, полученная делением одного родительского блока, является парой buddy-блоков.

---

# 2. Зачем нужен Buddy allocator

Когда программа просит память, например 100 КБ, выделять ровно 100 КБ сложно: память быстро фрагментируется, появляются маленькие неудобные свободные участки.

Buddy allocator решает эту проблему так:

```text
Запрос: 100 КБ
Ближайшая степень двойки: 128 КБ
Выделяется блок 128 КБ
```

То есть памяти выделяется немного больше, чем нужно, зато управление становится проще и быстрее.

---

# 3. Основные понятия

## Блок памяти

Блок — это участок памяти фиксированного размера.

Примеры блоков:

```text
32 КБ
64 КБ
128 КБ
256 КБ
512 КБ
```

## Order / порядок блока

В Buddy allocator размеры блоков часто описываются через порядок — **order**.

Если минимальный блок равен 4 КБ, то:

| Order | Размер блока |
| ----: | -----------: |
|     0 |         4 КБ |
|     1 |         8 КБ |
|     2 |        16 КБ |
|     3 |        32 КБ |
|     4 |        64 КБ |
|     5 |       128 КБ |
|     6 |       256 КБ |
|     7 |       512 КБ |
|     8 |      1024 КБ |

Формула:

```text
Размер блока = минимальный_размер × 2^order
```

Например, если минимальный блок 4 КБ:

```text
order 3 = 4 КБ × 2^3 = 32 КБ
```

## Buddy-блок

Buddy-блок — это соседний блок такого же размера, полученный из того же родительского блока.

Например, блок 512 КБ делится на два блока по 256 КБ:

```text
512 КБ
├── 256 КБ  ← блок A
└── 256 КБ  ← buddy блока A
```

Если оба buddy-блока свободны, их можно объединить обратно в один большой блок.

---

# 4. Структура данных Buddy allocator

Обычно allocator хранит несколько списков свободных блоков.

Каждый список отвечает за блоки определенного размера.

Например:

```text
free_list[0] → свободные блоки по 4 КБ
free_list[1] → свободные блоки по 8 КБ
free_list[2] → свободные блоки по 16 КБ
free_list[3] → свободные блоки по 32 КБ
free_list[4] → свободные блоки по 64 КБ
free_list[5] → свободные блоки по 128 КБ
free_list[6] → свободные блоки по 256 КБ
free_list[7] → свободные блоки по 512 КБ
free_list[8] → свободные блоки по 1024 КБ
```

В начале вся память свободна, поэтому есть один большой блок:

```text
free_list[8] → [1024 КБ]
free_list[7] → пусто
free_list[6] → пусто
...
free_list[0] → пусто
```

# 5. Как происходит выделение памяти

Допустим, у нас есть 1024 КБ свободной памяти, а программа просит 100 КБ.

## Шаг 1. Округляем размер вверх

Запрос:

```text
100 КБ
```

Ближайшая степень двойки:

```text
128 КБ
```

Значит, нужен блок размером 128 КБ.

## Шаг 2. Проверяем список свободных блоков 128 КБ

Если в `free_list[128 КБ]` есть свободный блок, allocator сразу его выдает.

Но в начале у нас есть только один блок 1024 КБ:

```text
free_list[1024 КБ] → [1024 КБ]
free_list[128 КБ] → пусто
```

## Шаг 3. Берем ближайший больший блок

Allocator ищет блок большего размера.

Он находит 1024 КБ и начинает делить его пополам:

```text
1024 КБ → 512 КБ + 512 КБ
```

Один блок 512 КБ оставляется для дальнейшего деления, второй кладется в список свободных блоков 512 КБ.

Затем:

```text
512 КБ → 256 КБ + 256 КБ
```

Один 256 КБ делится дальше, второй кладется в список свободных блоков 256 КБ.

Затем:

```text
256 КБ → 128 КБ + 128 КБ
```

Один блок 128 КБ выдается программе, второй кладется в список свободных блоков 128 КБ.

Итог:

```text
Выдано программе: 128 КБ

Свободно:
512 КБ
256 КБ
128 КБ
```

Схематично:

```text
1024 КБ
├── 512 КБ свободен
└── 512 КБ
    ├── 256 КБ свободен
    └── 256 КБ
        ├── 128 КБ свободен
        └── 128 КБ занят
```

# 6. Пример выделения нескольких блоков

Пусть начальная память — 1024 КБ.

## Запрос 1: выделить 100 КБ

Округляем до 128 КБ.

```text
Выделено: 128 КБ
```

Осталось:

```text
512 КБ свободен
256 КБ свободен
128 КБ свободен
```

## Запрос 2: выделить 200 КБ

Округляем до 256 КБ.

В списке свободных блоков уже есть 256 КБ, поэтому allocator просто берет его.

```text
Выделено: 256 КБ
```

Осталось:

```text
512 КБ свободен
128 КБ свободен
```

## Запрос 3: выделить 60 КБ

Округляем до 64 КБ.

Свободного блока 64 КБ нет, но есть блок 128 КБ.

Делим:

```text
128 КБ → 64 КБ + 64 КБ
```

Один блок 64 КБ выдается, второй остается свободным.

Итог:

```text
Занято:
128 КБ
256 КБ
64 КБ

Свободно:
512 КБ
64 КБ
```

# 7. Как происходит освобождение памяти

Освобождение — сильная сторона Buddy allocator.

Когда программа освобождает блок, allocator проверяет: свободен ли его buddy?

Если buddy свободен, два блока объединяются в один блок большего размера.

## Пример

Допустим, у нас есть два блока по 64 КБ:

```text
128 КБ
├── 64 КБ занят
└── 64 КБ свободен
```

Если занятый блок освобождается, получается:

```text
128 КБ
├── 64 КБ свободен
└── 64 КБ свободен
```

Так как оба buddy-блока свободны, они объединяются:

```text
128 КБ свободен
```

После этого allocator проверяет buddy уже для блока 128 КБ.

Если соседний 128 КБ тоже свободен, они объединяются в 256 КБ:

```text
256 КБ свободен
```

И так далее, пока объединение возможно.

---

# 8. Подробный пример освобождения

Допустим, память была разделена так:

```text
1024 КБ
├── 512 КБ свободен
└── 512 КБ
    ├── 256 КБ занят
    └── 256 КБ
        ├── 128 КБ занят
        └── 128 КБ
            ├── 64 КБ занят
            └── 64 КБ свободен
```

Теперь освобождаем блок 64 КБ.

Получается:

```text
64 КБ свободен
64 КБ свободен
```

Они объединяются:

```text
128 КБ свободен
```

Теперь проверяем buddy этого 128 КБ.

Но рядом есть занятый блок 128 КБ:

```text
128 КБ занят
128 КБ свободен
```

Объединить нельзя.

Итог: свободный блок 128 КБ добавляется в список свободных блоков.

# 9. Как найти buddy-блок

В buddy allocator адрес buddy-блока можно вычислить очень быстро.

Если блок имеет адрес `addr`, а его размер `size`, то адрес buddy обычно вычисляется так:

```text
buddy_addr = addr XOR size
```

Операция XOR переключает бит, отвечающий за размер блока.

Пример:

```text
addr = 0
size = 128
buddy = 0 XOR 128 = 128
```

Значит, buddy блока `[0; 127]` — блок `[128; 255]`.

Другой пример:

```text
addr = 128
size = 128
buddy = 128 XOR 128 = 0
```

Значит, buddy блока `[128; 255]` — блок `[0; 127]`.

Это делает алгоритм очень быстрым.

# 10. Алгоритм выделения памяти

Упрощенно:

```text
allocate(size):
    1. Округлить size до ближайшей степени двойки.
    2. Найти order для этого размера.
    3. Если есть свободный блок нужного order:
        взять его и вернуть.
    4. Иначе найти ближайший больший свободный блок.
    5. Делить его пополам, пока не получится блок нужного размера.
    6. Один блок вернуть пользователю.
    7. Остальные половины добавить в списки свободных блоков.
```

Псевдокод:

```c
void* allocate(size_t size) {
    int order = find_order(size);

    for (int current = order; current <= MAX_ORDER; current++) {
        if (!free_list[current].empty()) {
            block = free_list[current].remove_first();

            while (current > order) {
                current--;

                buddy = split(block);
                free_list[current].add(buddy);
            }

            mark_as_used(block);
            return block.address;
        }
    }

    return NULL;
}
```

# 11. Алгоритм освобождения памяти

```text
free(block):
    1. Определить размер блока и его order.
    2. Найти buddy-блок.
    3. Если buddy свободен и имеет тот же order:
        удалить buddy из списка свободных блоков;
        объединить блоки;
        перейти на order выше;
        повторить проверку.
    4. Если buddy занят или имеет другой размер:
        добавить блок в список свободных блоков.
```

Псевдокод:

```c
void free(void* ptr) {
    block = get_block(ptr);
    int order = block.order;

    while (order < MAX_ORDER) {
        buddy = find_buddy(block, order);

        if (!buddy.is_free || buddy.order != order) {
            break;
        }

        free_list[order].remove(buddy);
        block = merge(block, buddy);
        order++;
    }

    free_list[order].add(block);
}
```

# 12. Внутренняя фрагментация

Главный минус Buddy allocator — внутренняя фрагментация.

Поскольку память выделяется блоками степени двойки, программа может получить больше памяти, чем просила.

Например:

|Запрошено|Выделено|Потери|
|--:|--:|--:|
|33 КБ|64 КБ|31 КБ|
|65 КБ|128 КБ|63 КБ|
|129 КБ|256 КБ|127 КБ|

Самый неприятный случай — когда запрос чуть больше половины блока.

Например:

```text
Запрос: 129 КБ
Выделение: 256 КБ
Потери: 127 КБ
```

---

# 13. Внешняя фрагментация

Внешняя фрагментация — это ситуация, когда свободная память есть, но она разбита на куски, и большой непрерывный блок выделить нельзя.

Buddy allocator уменьшает внешнюю фрагментацию, потому что умеет быстро объединять buddy-блоки.

Например:

```text
64 КБ свободен + 64 КБ свободен = 128 КБ свободен
128 КБ свободен + 128 КБ свободен = 256 КБ свободен
```

Но полностью проблему внешней фрагментации он не решает.

Если свободные блоки не являются buddy-блоками, объединить их нельзя.

Пример:

```text
64 КБ свободен
64 КБ занят
64 КБ свободен
64 КБ занят
```

Свободной памяти всего 128 КБ, но выделить один блок 128 КБ невозможно, потому что свободные участки не соседние buddy-блоки.

---

# 14. Почему buddy-блоки можно объединять только попарно

Buddy allocator хранит историю деления памяти.

Если блок 256 КБ был разделен на два блока по 128 КБ, то только эти два блока можно снова объединить.

Например:

```text
256 КБ
├── 128 КБ A
└── 128 КБ B
```

A и B — buddy.

Но если рядом находятся два блока по 128 КБ, которые произошли от разных родительских блоков, они не объединяются.

```text
256 КБ родитель 1       256 КБ родитель 2
├── 128 КБ A            ├── 128 КБ C
└── 128 КБ B            └── 128 КБ D
```

Блоки B и C могут физически лежать рядом, но они не являются buddy, поэтому allocator их не объединит.

---

# 15. Преимущества Buddy allocator

## 1. Быстрое выделение памяти

Allocator не перебирает всю память. Он смотрит в списки свободных блоков нужного размера.

## 2. Быстрое освобождение памяти

Buddy-блок находится через простую операцию:

```text
buddy_addr = addr XOR size
```

## 3. Простое объединение блоков

Если buddy свободен, блоки объединяются.

## 4. Хорошо подходит для системного уровня

Buddy allocator удобен для ядра ОС, драйверов, низкоуровневого управления страницами памяти.

## 5. Уменьшает внешнюю фрагментацию

Благодаря объединению buddy-блоков allocator может восстанавливать большие свободные блоки.

---

# 16. Недостатки Buddy allocator

## 1. Внутренняя фрагментация

Запросы округляются до степени двойки.

Например:

```text
Запрос 130 КБ → выделяется 256 КБ
```

Почти половина блока может не использоваться.

## 2. Не всегда эффективно для маленьких объектов

Для объектов по 24, 40, 56 байт выделение блоков степени двойки может быть невыгодным.

Поэтому в ОС Buddy allocator часто комбинируют с другими аллокаторами, например со slab allocator.

## 3. Можно объединять только buddy-блоки

Даже если два свободных блока лежат рядом, они не обязательно могут быть объединены.

## 4. Требуется хранить метаданные

Allocator должен знать:

```text
размер блока;
свободен он или занят;
его order;
ссылки на списки свободных блоков.
```

---

# 17. Где используется Buddy allocator

Buddy allocator используется там, где нужно управлять крупными блоками памяти:

```text
ядра операционных систем;
управление физическими страницами памяти;
драйверы;
встраиваемые системы;
реализация низкоуровневых memory pools;
игровые движки;
real-time системы.
```

В Linux buddy allocator используется для управления физическими страницами памяти. А для маленьких объектов поверх него часто работают другие механизмы, например slab/slub allocator.

---

# 18. Buddy allocator и страницы памяти

В операционных системах минимальная единица часто равна странице памяти.

Например:

```text
1 страница = 4 КБ
```

Тогда buddy allocator управляет блоками из нескольких страниц:

|Order|Количество страниц|Размер при 4 КБ странице|
|--:|--:|--:|
|0|1|4 КБ|
|1|2|8 КБ|
|2|4|16 КБ|
|3|8|32 КБ|
|4|16|64 КБ|
|5|32|128 КБ|
|6|64|256 КБ|
|7|128|512 КБ|
|8|256|1024 КБ|

Если ядру нужно выделить 16 страниц, оно ищет блок order 4.

# 19. Пример работы с адресами

Пусть есть память от адреса `0` до `1023`.

Размер всей памяти:

```text
1024 байта
```

Минимальный блок:

```text
128 байт
```

Тогда возможные блоки:

```text
128, 256, 512, 1024
```

Начальное состояние:

```text
[0–1023] свободен
```

Запрос: 200 байт.

Округляем:

```text
200 → 256
```

Делим:

```text
[0–1023]
├── [0–511]
└── [512–1023] свободен
```

Делим `[0–511]`:

```text
[0–511]
├── [0–255] выделен
└── [256–511] свободен
```

Состояние:

```text
[0–255] занят
[256–511] свободен
[512–1023] свободен
```

Теперь запрос: 100 байт.

Округляем:

```text
100 → 128
```

Берем свободный блок `[256–511]` размером 256 и делим:

```text
[256–511]
├── [256–383] выделен
└── [384–511] свободен
```

Состояние:

```text
[0–255] занят
[256–383] занят
[384–511] свободен
[512–1023] свободен
```

Теперь освобождаем `[256–383]`.

Его buddy:

```text
[384–511]
```

Он свободен, значит объединяем:

```text
[256–511] свободен
```

Теперь проверяем buddy для `[256–511]`.

Buddy блока `[256–511]` размером 256 — это `[0–255]`.

Но `[0–255]` занят, поэтому дальше объединять нельзя.

Итог:

```text
[0–255] занят
[256–511] свободен
[512–1023] свободен
```

# 20. Сравнение с обычным allocator

Обычный allocator может выделять почти ровно столько, сколько попросили:

```text
100 байт → 100 байт
```

Buddy allocator выделяет степень двойки:

```text
100 байт → 128 байт
```

Зато buddy allocator быстрее и проще объединяет память.

|Критерий|Buddy allocator|
|---|---|
|Скорость выделения|высокая|
|Скорость освобождения|высокая|
|Простота реализации|средняя|
|Внутренняя фрагментация|возможна|
|Внешняя фрагментация|меньше, чем у простых схем|
|Подходит для ОС|да|
|Подходит для маленьких объектов|не идеально|

# 21. Краткая схема работы

```text
Выделение памяти:

1. Получить размер запроса.
2. Округлить до ближайшей степени двойки.
3. Найти список свободных блоков нужного размера.
4. Если блок есть — выдать.
5. Если блока нет — взять больший блок.
6. Делить больший блок пополам.
7. Одну половину использовать, вторую сохранить как свободную.
```

```text
Освобождение памяти:

1. Получить освобождаемый блок.
2. Найти его buddy.
3. Если buddy свободен — объединить.
4. Повторять объединение вверх.
5. Если объединять нельзя — положить блок в список свободных.
```

# 22. Самое важное простыми словами

Buddy allocator работает так:

```text
Большой блок памяти делится пополам.
Половины снова могут делиться пополам.
Когда нужно выделить память, выбирается минимальный подходящий блок степени двойки.
Когда память освобождается, allocator пытается объединить блок с его парным buddy-блоком.
```

Главная сила Buddy allocator — быстрое объединение памяти после освобождения.

Главный минус — выделяется не точный размер, а ближайшая степень двойки, поэтому часть памяти может тратиться впустую.
