**CRx (Control Registers)** — это набор специальных регистров процессора x86/x86-64, которые управляют:

- режимами работы CPU
- виртуальной памятью
- защитой памяти
- прерываниями
- расширениями процессора

Они доступны **только в режиме ядра (ring 0)**.

## Список регистров

| Регистр | Назначение                         |
| ------- | ---------------------------------- |
| CR0     | Основное управление режимами CPU   |
| CR1     | не используется                    |
| CR2     | Адрес ошибки страницы (Page Fault) |
| CR3     | Таблица страниц (MMU)              |
| CR4     | Расширенные функции CPU            |
| CR8     | Приоритет прерываний (x86-64)      |

---

# CR0 — главный регистр управления

CR0 = control flags bitmask

CR0 включает базовые режимы процессора.

### Основные биты:

| Бит | Название               | Описание                              |
| --- | ---------------------- | ------------------------------------- |
| 0   | PE (Protection Enable) | Включает защищённый режим             |
| 1   | MP                     | Контроль FPU                          |
| 2   | EM                     | Эмуляция FPU                          |
| 3   | TS                     | Task switched                         |
| 16  | WP                     | Защита страниц даже в kernel          |
| 29  | NW                     | No Write-through                      |
| 30  | CD                     | Cache Disable                         |
| 31  | PG                     | Paging (включение виртуальной памяти) |

### Важно:
- **PE = 1 → Protected Mode**
- **PG = 1 → Paging включён**
# CR2 — адрес ошибки страницы

Используется при исключении **Page Fault (#PF)**.

Когда происходит ошибка памяти:
- CR2 содержит **адрес, к которому был доступ**
Пример:
```
segfault → читаем CR2 → узнаём где ошибка
```

# CR3 — сердце виртуальной памяти

CR3 = Physical address of page directory
CR3 хранит:
- адрес таблицы страниц (Page Directory / PML4 в x64)
### Что делает:

- переключает адресное пространство процесса
    
- используется при context switch
    

###  Факт:

Каждый процесс → свой CR3

Переключение CR3 = смена процесса

---

# 6. CR4 — расширенные возможности

CR4 включает дополнительные фичи CPU.

### Основные биты:

| Бит | Название   | Описание                       |
| --- | ---------- | ------------------------------ |
| 0   | VME        | Virtual 8086 mode              |
| 4   | PSE        | Большие страницы (4MB)         |
| 5   | PAE        | Расширенная адресация (36-bit) |
| 7   | PGE        | Global pages                   |
| 9   | OSFXSR     | SSE поддержка                  |
| 10  | OSXMMEXCPT | SSE exceptions                 |
| 13  | VMXE       | Виртуализация (Intel VT-x)     |
| 16  | FSGSBASE   | Работа с FS/GS                 |
| 18  | OSXSAVE    | AVX                            |

# 7. CR8 (только x86-64)

Управляет приоритетом прерываний:

- задаёт уровень, ниже которого прерывания игнорируются

Используется в:

- ядре ОС
- системах реального времени
# 8. Привилегии и безопасность

CRx доступны только:

- ring 0 (kernel mode)
    

Попытка доступа из user mode →  **исключение (General Protection Fault)**

# 9. Работа с CRx (Assembler)

### Чтение:
```asm
mov eax, cr0
```
### Запись:
```asm
mov cr0, eax
```
### Пример: включение paging
```asm
mov eax, cr0
or eax, 0x80000000   ; PG бит
mov cr0, eax
```
# 10. Связь с виртуальной памятью
Последовательность включения:
1. Настроить таблицы страниц
2. Загрузить их адрес в CR3
3. Включить PG в CR0
# 11. Частые ошибки
 Неправильный CR3 → crash  
 Включение PG без таблиц → triple fault  
 Доступ из user mode → exception
# 12. Как это используют ОС
### Windows / Linux:
- управление процессами → через CR3
- защита памяти → CR0 + CR4
- page fault handler → CR2
# 13. Связь с другими механизмами
CRx работают вместе с:
- MMU (Memory Management Unit)
- TLB (Translation Lookaside Buffer)
- Page Tables
- IDT (Interrupt Descriptor Table)
